5. Hanif: "let's see where we are in terms of like the code that we're pushing. Can we do some adversarial tests first?" An independent reviewer tried to break the branch. It found one real bug: an open redirect. `/login?next=/%09/evil.com` passed `safeNextPath`, because the check looked only at the character after the first `/`, and a browser deletes tab, LF and CR from a URL. After the log-in, the user went to evil.com. The log-in form made this reachable with only a link (the email callback had the same check, but it needs a valid code). How we repaired it: a red test first (tab, LF, CR, NUL and backslash cases in `tests/auth.test.ts`), then `safeNextPath` refuses control characters and backslashes anywhere. Smaller fixes from the review: a logged-in user on `/login?next=…` goes to that page, not the lobby; the shared page sends a visitor to the log-in if the database refuses the call (42501), as a second guard.
