Key prompts that shaped the plan. The plan was drafted with Claude and then edited by Hanif.

1. "Read it and then outline the plan for the solo app. We want to be able to, by the end of the development, create an app that is useful for us. Fun duolingo app style game where we learn about hardware (focus on ESP wiring)."
2. "I want to be able to wire while learning the breadboard. It would involve some sort of 3D interface."
3. "The idea is to have a showcase of one project where the user goes through a project to learn about wiring an ESP 32."
4. "Let's do a home for our AI Agent (like the new apple home device or the muse sdk projects)."
5. "We're not going to work on the hardware physically, but we're going to learn about working on the hardware digitally."

7. Pitch: "I'm building Jumper, a web app where you learn how to wire boards and learn about hardware engineering..." with the reason "because I want to understand hardware without buying a bench full of parts." Usage: "I would use it 3 times a week."
8. "There should be a feature: lobby to see project catalog; step by step for each process of wiring and setting up the board; Perch build needs to be guided like a game."
9. "Perch game is only an example. All levels or builds will react the same way... players can see pop ups that help guide them... The pop ups are important because it should be part of the learning process."

## Decisions made by Hanif

- Fully digital: no physical hardware.
- One playable project (Perch); all others "Coming soon".
- Sharing and collaboration are future work, shown in the app as "Coming soon".
- Phone support for wiring is required.
- Data must record completed sessions.
